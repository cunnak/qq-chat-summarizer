# QQ 群聊总结助手 (qq-chat-summarizer)

自动留档 QQ 群聊消息，按话题自动切分并调用大模型总结，支持图片内容理解（多模态）。

基于 [NapCat](https://github.com/NapNeko/NapCatQQ)（OneBot 11 协议）工作，自带**网页控制台**，改配置不用碰代码。

## 功能

- 📝 **自动留档**：群消息（含图片、小程序卡片）存入本地 SQLite
- ✂️ **话题切分**：群内 30 分钟（可配）无人发言自动判定话题结束
- 🤖 **自动总结**：话题结束调用 LLM 生成标题/要点/总结，发回群里
- 🖼 **图片理解**：多模态模型可直接读取群聊截图/图表内容进总结
- 🎯 **兴趣度打分**（v1.1+）：设置兴趣关键词（如"政策、房价"），每个话题自动打 0-100 兴趣分并附理由；高分话题可选自动推送提醒；历史页按分数排序；可对话题标记"不感兴趣"（负分沉底）
- 🎛 **三种模型模式**（控制台随时切换）：
  - 单一多模态模型（推荐，一个模型总结+看图）
  - 纯文本模型（不看图，成本最低）
  - 文本主模型 + 视觉辅助模型（两个模型分工）
- ✋ **手动触发**：群里发「总结一下」立即总结当前话题（权限/冷却可配）
- 📰 **每日日报**：可选每天定时汇总当日全部话题
- 📊 **网页控制台**：仪表盘（消息/话题/LLM调用/token/费用估算）、历史话题浏览与重新生成、兴趣打分与反馈、运行日志、数据导出/备份、一键重启
- 👥 **多群独立配置**：每个群单独设置监控开关、总结/存档发到哪、总结风格
- 🔐 **密码登录**：控制台带鉴权，聊天记录不裸奔

## 🆕 v1.1.1 更新说明

**修复：多模态模式下图片总结失败（400 Bad Request）**

- **问题**：群聊图片 URL 是腾讯内部域名 + 短时效签名，公网模型服务商（如阿里云百炼）直接拉取会报 `400 Failed to download multimodal content`，导致话题含图片时总结失败。
- **修复**：改为**本地下载图片 → base64 编码 → 随请求发送**给模型。本机（NapCat 同机）先把图片下载到临时目录 `img_tmp/`，转成 base64 data URI 后发给多模态模型，模型可直接看图总结。
- **临时文件自动清理**：每次总结结束（无论成功或失败）自动清空 `img_tmp/` 目录，不占硬盘空间。
- **兜底保护**：单次总结最多下载 10 张图片（防请求过大/超时）；单张图片下载失败自动跳过，不阻断总结。
- **适用模式**：`multimodal`（单一多模态）与 `dual`（文本+视觉辅助）两种模式均生效。

## 快速开始（Windows，零基础友好）

1. 下载 Release 中的 `qq-chat-summarizer-windows-x64.zip`，解压到任意目录
2. 双击 `群聊总结助手.exe`
3. 浏览器自动打开配置向导（没弹就手动访问 http://127.0.0.1:8787）
4. 按向导依次完成：设置控制台密码 → 连接 NapCat → 配置大模型 → 选择监控群
5. 完成，机器人开始工作

> **前置要求**：需要一个运行中的 [NapCat](https://github.com/NapNeko/NapCatQQ)（QQ 机器人协议端，免费开源），并为其配置一个**不常用的 QQ 小号**登录。
> 没装过？向导第 1 步有详细指引。⚠️ 挂框架的号有被腾讯风控的风险，请务必用小号。

## 快速开始（Linux 服务器）

```bash
unzip server-deploy.zip && cd qq-chat-summarizer
sudo bash deploy/deploy.sh
# 服务: qq-chat-summarizer (systemd, 开机自启+崩溃重启)
# 控制台: http://服务器IP:8787  ← 记得防火墙放行, 首次进入设置密码
```

或手动运行：

```bash
pip install -r requirements.txt
python main.py
```

## 大模型配置（任选一家，OpenAI 兼容接口均可）

| 服务商 | base_url | 模型示例 |
|---|---|---|
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` / `qwen-vl-plus` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4` |

**模式选择建议**：
- 想让总结包含群里的截图/图片内容 → 选「单一多模态模型」（如 `qwen-vl-plus`）
- 只总结文字 → 「纯文本模型」（如 `deepseek-chat`），成本最低
- 主模型没视觉能力但想看图 → 「文本主模型 + 视觉辅助模型」（主模型总结，便宜视觉模型如 `qwen3-vl-flash` 提取图片文字）

## 配置说明

所有配置在网页控制台修改，保存即生效。配置文件为 `config.json`（首次运行自动生成）：

| 配置组 | 关键项 |
|---|---|
| LLM | `mode`（text/dual/multimodal）、`api_key`、`base_url`、`model`、视觉辅助模型 |
| 机器人 | NapCat 正向 WS 地址与 token |
| 触发 | 指令文字、权限（所有人/管理员）、冷却秒数 |
| 话题 | 空闲判定秒数、最少消息数 |
| 日报 | 开关、时间、发送群号 |
| 群 | 每群：监控开关、总结发到哪、md 存档发到哪、风格 |

## 常见问题

**Q: 控制台打不开？** 检查端口 8787 是否被占用（`--port 9000` 可换端口）；云服务器需在安全组放行。

**Q: 连不上 NapCat？** 确认 NapCat 已运行、正向 WS 地址/端口/token 与 NapCat 的 `onebot11` 配置一致。

**Q: 总结没触发？** 话题需要 ≥3 条消息（可配）且群内安静满 30 分钟；或群里发触发指令手动总结。

**Q: 图片没进总结？** 确认模式选了「多模态」且模型支持视觉（如 qwen-vl 系列）；纯文本模型看不到图片。

**Q: md 存档发不出去？** 部分 NapCat 版本对群文件上传支持不同，存档群填 0 可关闭，本地 `archive_md/` 目录始终保留全部存档。
